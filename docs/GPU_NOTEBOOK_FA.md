# اجرای مدل پارسل گاوسی روی GPU

فایل اصلی: [GaussianParcelPINN_GPU.ipynb](../GaussianParcelPINN_GPU.ipynb).
این notebook مربوط به مدل اصلی کانال دوبعدی و کوپل دوطرفهٔ گاوسی است؛ افزونهٔ دوران استوانه را اجرا نمی‌کند.

## استفاده

1. notebook را در Google Colab باز کنید؛ از Runtime → Change runtime type کارت GPU را فعال کنید.
2. گزینهٔ Run all را بزنید. کد و داده‌های تحلیلی لازم داخل خود notebook قرار دارند؛ clone یا آپلود جداگانه لازم نیست.
3. در پایان، ZIP نتایج را دریافت کنید. گزارش آفلاین `index.html` را پس از استخراج ZIP باز کنید.

روی Kaggle و Jupyter دارای CUDA هم قابل استفاده است. PyTorch با پشتیبانی CUDA و نسخهٔ حداقل ۲٫۲ باید از قبل نصب باشد.
نصب وابستگی‌ها نسخهٔ CUDA را با PyTorch مبتنی بر CPU جایگزین نمی‌کند.
فقط اگر وابستگی‌ای غایب یا خارج از محدودهٔ نسخهٔ تعیین‌شده باشد، نصب می‌شود؛ نصب حداکثر چهار دقیقه فرصت دارد.
نبود GPU باعث توقف صریح notebook می‌شود.

## زمان و تنظیمات

بودجهٔ پیش‌فرض ۵۵ دقیقه از شروع اولین سلول محاسباتی است. حداکثر ۳۵ دقیقه برای آموزش چهار حالت
`low_inertia`، `baseline`، `high_loading` و `high_inertia` تقسیم می‌شود؛ زمان آماده‌سازی از کل بودجه کم می‌شود.
حداقل ۳۵٪ زمان اجرای solver برای ارزیابی، آزمون‌های تحلیلی، شکل‌ها، ویدیو و ZIP باقی می‌ماند.
بهترین checkpoint با batch ثابت در طول آموزش ذخیره می‌شود. آموزش در سقف زمانی متوقف می‌شود و خروجی از بهترین checkpoint ساخته می‌شود.
اگر معیارهای دقت پاس نشوند، رسم خروجی ادامه پیدا می‌کند. اگر یک مرحله واقعاً خراب شود یا از سقف زمانش عبور کند، در log و گزارش ثبت می‌شود.
برای پردازش‌های CUDA یا encoder متوقف‌شده، ناظر مستقل سقف زمانی دارد؛ برای کل اجرای solver هم watchdog در notebook وجود دارد.

این یک **بودجهٔ اجرا** است، نه وعدهٔ رسیدن به خطای مشخص یا تکمیل همهٔ شکل‌ها روی هر دستگاه.
سرعت GPU، قطع محیط ابری، نصب، زمان ذخیره در Drive و دانلود ZIP قابل تضمین نیستند.
نمایش همهٔ شکل‌ها در notebook و دانلود ZIP پس از محاسبات انجام می‌شود؛ انتقال فایل به دستگاه شما بخشی از زمان آموزش نیست.
اگر زمان ناکافی باشد، خروجی ناقص با وضعیت صریح حفظ می‌شود؛ دادهٔ مصنوعی جای حل شبکه قرار نمی‌گیرد.
معیارهای باقی‌ماندهٔ معادلات همان معیارهای پروژه هستند؛ این معیارها درصد خطا در برابر مقاله نیستند.

متغیرهای سلول اول:

| متغیر | پیش‌فرض | کاربرد |
|---|---:|---|
| `TOTAL_MINUTES` | 55 | بودجهٔ کل؛ حداکثر ۵۵ دقیقه |
| `TRAIN_MINUTES` | 35 | بودجهٔ کل آموزش، تقسیم بین چهار حالت |
| `PRECISION` | float32 | دقت آموزش GPU؛ float64 اختیاری و روی T4 بسیار کندتر است |
| `OUTPUT_BASE` | gaussian_gpu_results | پوشهٔ ذخیره؛ هر اجرا پوشهٔ مستقل دارد |

در هر حالت، شش پارسل، دو شبکهٔ tanh با سه لایهٔ پنهان ۴۸ نرونی، quadrature برابر ۲۴×۲۰،
۴ زمان و ۹۶ نقطهٔ مکانی در batch آموزش و ۴۱ frame خروجی استفاده می‌شود.
آموزش Adam است؛ AMP و TF32 خاموش‌اند تا مشتقات معادلات با دقت کامل float32 محاسبه شوند.
ارزیابی و رسم روی CPU با float64 انجام می‌شود؛ این تبدیل، دقت آموزش انجام‌شده را افزایش نمی‌دهد.
یک seed برای هر حالت استفاده می‌شود؛ نوار عدم قطعیت آماری ادعا نمی‌شود.

## خروجی‌ها

- ساختار شبکه و تبادل نیرو با کرنل گاوسی؛
- میدان سرعت، فشار، ورتیسیته و کسر حجمی، پروفیل کانال و خطوط جریان؛
- snapshot حرکت و توزیع گاوسی، مسیر و سرعت پارسل‌ها، مقایسهٔ حالت‌ها؛
- نمای عمق‌دار کانال و سطح سه‌بعدی سرعت؛ حل فیزیکی همچنان دوبعدی است؛
- تاریخچهٔ آموزش، انرژی، اتلاف و باقی‌ماندهٔ موازنهٔ تکانه و انرژی؛
- انیمیشن حرکت مراکز و انیمیشن ابرهای گاوسی برای هر حالت، GIF و در صورت وجود ffmpeg فایل MP4؛
- نمودارهای مقایسهٔ تحلیلی Stokes، تبادل تکانه، هم‌پوشانی گاوسی و Taylor–Green؛
- PNG/PDF/SVG، CSV، LaTeX، fields.npz، checkpoint.pt، گزارش HTML/Markdown/JSON، log و ZIP.

در انیمیشن گاوسی، پهنا ثابت است و کرنل حول مسیر پیش‌بینی‌شده جابه‌جا می‌شود.
این انیمیشن نشان‌دهندهٔ پخش براونی یا تکامل پهنای پارسل نیست.
سرعت درگ از سیال دارای اغتشاش نمونه‌برداری می‌شود؛ تصحیح self-disturbance و فیزیک ERPP در این مدل پیاده نشده است.
V01–V10 بررسی عددی اجزای مدل هستند؛ اعتبارسنجی مستقیم کل مدل در برابر مقاله نیستند.
تعداد اعتبارسنجی‌های مقاله‌ای در گزارش این workflow برابر صفر باقی می‌ماند.

## اجرای خط فرمان و بازتولید

```bash
python run_gpu.py --device cuda --precision float32 --max-minutes 55 --train-minutes 35 --out outputs/gpu_run_01
```

هرگز نام پوشهٔ خروجی قبلی را برای اجرای جدید استفاده نکنید. تنظیمات واقعی، GPU و زمان در فایل‌های
`config.json`، `runtime.json`، `run_settings.json`، `stage_status.json` و `completion.json` ذخیره می‌شوند.
ZIP شامل یک نسخهٔ کد دقیق اجرای شماست. `FINAL_COMPLETION.json` داخل ZIP، وضعیت نهایی بسته‌بندی را دارد؛ checksum کنار ZIP ذخیره می‌شود.

برای بازتولید notebook و بستهٔ کد از سورس خوانا:

```bash
python build_gpu_notebook.py
```

برای تست کوتاه مسیر اجرا روی CPU، با خروجی تشخیصی و بدون ادعای دقت:

```bash
python run_gpu.py --device cpu --precision float32 --smoke --max-minutes 6 --train-minutes 0.3 --out outputs/gpu_workflow_smoke
```

محدودیت‌های کیفیت علمی و نتایج آزمون واقعی محیط توسعه در [گزارش بررسی‌ها در GitHub](https://github.com/mohrezsayeh90-ai/final_cloud_code/blob/main/docs/GPU_EXECUTED_CHECKS.md) ثبت می‌شوند.
